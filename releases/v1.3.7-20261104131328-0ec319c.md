# Podhoc 1.3.7 — clearer controls, sharing and support

This release brings together the product changes since Podhoc 1.3.4. Availability can differ by platform, subscription provider and enabled capability. Mobile improvements require the updated app to pass the relevant store review; deploying the website does not update an installed app.

## New and improved

- **A clearer start.** New accounts receive a guided introduction to creation, listening and publication. Existing accounts retain their recorded onboarding status.
- **Publication choices explained.** Completed Free episodes publish to Discover. Creator and Pro can choose private episodes; a credit top-up does not add that entitlement. Source files remain private, but public audio, titles, summaries and artwork can reveal their contents. Publication safeguards help prevent private or deleted episodes from resurfacing through stale background work.
- **Support together.** Feedback and My Tickets share one Support area on web and mobile, with private conversations kept separate from community feedback.
- **Sharing where you need it.** Eligible public episodes have copy-link, system-share and X/Bluesky options. Private sharing remains account-based. My Podcasts offers the embed snippet alongside Discover, with clearer previews, readable titles and uncropped artwork. Sharing does not automatically make a private episode public.
- **A consistent interface.** Theme, compact mode and language controls align more clearly. Dialogs, episode details and players follow the chosen light or dark theme. Blocked-content messages are translated, and Delete is separated from Play.

## Subscription and generation controls

Account screens explain how to manage a paid subscription with its actual provider: Stripe, Apple or Google. Cancellation and plan changes depend on the provider and enabled options. A plan granted by an administrator is not a paid subscription. Provider confirmation determines renewal and end dates; closing a management screen is not proof that a change completed.

Stopping an eligible generation requires a separate capability rollout. Where enabled, owners can request cancellation while an eligible episode is being created. A task already running with an external provider may take time to stop. The result shows any restored credits; retries do not create extra compensation, and an episode that finished first cannot be cancelled retroactively. This is not a promise to stop every provider operation instantly.

## Reliability

Sign-in and session restoration handle key rotation and additional identity claims more reliably. Loading failures have clearer recovery instead of leaving an unusable blank screen. The completion-email recipient lookup is corrected, and generation recovery, deployment safeguards and diagnostics for API and webhook failures are improved.

## Agent integrations and Telegram

Downloadable agent tools document explicit publication choices, delegated permissions, expiry and credit limits. The agent bundle has its own version, independent of this app release. REST is the baseline integration; MCP requires separate activation and authenticated client verification. Downloading or installing a package does not mean it is listed in a public marketplace. These tools cannot buy subscriptions or cancel generation.

Telegram account linking adds a clearer consent step. Bot configuration and an owner sign-in roundtrip must be verified separately for each environment. These notes do not assert that every bot, MCP transport, marketplace listing or store build is already available.
